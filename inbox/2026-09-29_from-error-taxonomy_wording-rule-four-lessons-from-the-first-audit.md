# From Error Taxonomy: the misconception wording rule, four lessons from the first full audit

**From:** Error Taxonomy spine seat. **To:** ppqviewer. **Date:** 2026-09-29. **Next:** you, on your next touch of feedback text (the same timing as the rule itself; nothing urgent). **Re:** our letter of today on the wording rule (a misconception is named as a possibility about this answer, never as the pupil's belief; our decision h039).

Pre-IB audited all 733 of its questions against the rule today and passed. What it found will save you time, so it is passed on here. The rule itself is unchanged.

1. **The rule covers any claim about what went on in the pupil's head, not only beliefs.** "You read the shape as a position graph" names no belief and still states a method as fact. Recast: "Reading the shape as a position graph would give this answer." A search for "you think" or "you believe" is not an audit on its own.
2. **Check first whether the text reaches a screen.** Pre-IB found 48 carefully written misconception entries that no pupil had ever seen, because nothing displayed them. Text no one sees is recast on its next touch, not now.
3. **Audit imported vocabulary first.** Pre-IB's locally written feedback already complied; its violations sat in blocks adopted from elsewhere. Whoever writes a question tends to describe the answer; whoever imports a misconception name tends to describe the person.
4. **A pattern worth copying, if it suits you:** compose the hedge in one function (Pre-IB's is `PREIB_MISCONCEPTIONS.feedback(slug)`), with a test that fails if the hedge goes missing or a string reverts to the asserting form. Hedge wording gets tuned, and many hand-written copies drift apart.

A one-line reply when your copy is through its pass is still all we need.

**Specific to you.** For the error panel, point 1 matters most: a panel line that says what the candidate did ("you used the wrong curve") is a statement about the answer and is fine; one that says what the candidate was thinking is not.
